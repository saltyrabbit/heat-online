# HEAT · 中文联机赛车

非官方的 HEAT 中文联机版，支持基础规则、天气与路况、普通/高级车库，以及 Heavy Rain、Tunnel Vision、Rocky Roads 的单场比赛内容。包含十张官方赛道和原创「海岸环线」，采用原创 SVG 示意重绘。基础 2–6 人，每开启一个扩展盒增加一个席位，最多 9 人；可用电脑补位，支持房间码邀请、刷新恢复座位和房主启用电脑接管。

当前公网入口：[ParrotVPN](https://52.76.213.199/heat/)。旧 Sites 入口为早期版本，与此服务的房间独立。

## 开始比赛

1. 输入昵称，选择赛道和 1 圈练习赛或地图规定圈数的正式赛，创建房间。
2. 点击房间码或「邀请朋友」复制邀请链接；朋友输入自己的昵称并加入。
3. 房主可在大厅调整赛道、距离和六个独立模块/扩展开关，设置同步到其他车手；发车后锁定。房主在至少两名车手就位后开始比赛。需要时可添加电脑。
4. 开启任一车库时，先按官方三轮顺序选升级；天气先于车库公开。基础盒普通单独开启使用 34 张牌，高级单独开启使用 62 张牌，同时开启使用 96 张混合牌；每个启用的扩展盒在高级车库开启时再加入 12 张（6 种各两张）。
5. 每回合选择挡位与对应张数的牌并锁定。所有人确认后，按位置依次执行移动、反应、尾流与弯道检查。检查完成立即交接下一位；弃牌和补牌各自异步完成，全员收尾后进入下一回合。
6. 跑完规定圈数，服务器计算最终排名。界面内有完整玩法指南。

每位玩家应使用自己的浏览器。相同浏览器里的标签页共用身份；在一台电脑上测试两个座位时，请使用不同浏览器或隐私窗口。当前座位由浏览器 cookie 保存，清除 cookie 会丢失该座位。房间在最后一次操作后保留七天。

## 规则范围

实现基础换挡、同时选牌、逐车行动、压力牌翻牌、热量支付与冷却、每轮一次加速、肾上腺素、双车道占位、尾流、逐弯检查、打滑、过热停留、可选弃牌、洗牌补牌和同回合冲线排序。起始牌组含 12 张基础速度牌、0 与 5 起始升级、1 张起始热量、3 张压力；基础赛道引擎初始热量为 6；扩展赛道使用各地图的引擎与压力设置，再应用天气调整。

本版使用自定义的几何内侧优先规则：每格以示意赛道中心线的局部曲率决定内侧，反向弯换侧；直线沿用前一个弯的内侧，跨圈保持一致。落位优先该格内侧，已占用则落外侧，满格退让后重新按实际落点判断。回合顺序、末位奖励、界面排名和同回合冲线排序均使用相同判定。绿线逐格绘在该侧，两条物理车道不因弯向变化而互换编号。这一规则替代官方印刷 Race Line 的同格优先方式，以本程序原创示意图为准。

规则参考：https://www.daysofwonder.com/game/heat/

本版支持异步收尾：官方流程要求每位车手完成第 3–9 步后再轮到下一位；这里在第 7 步后就交接行动，第 8–9 步可与其他车手的行动并行。待收尾名单保存在房间中，可刷新恢复；不会提前开始下一回合，也不会改变车辆落位、反应、弯道支付或名次。页面按各玩家实际阶段高亮第 5 步（反应）和第 8 步（弃牌），选牌阶段高亮第 1–2 步；自动执行的阶段不会人为暂停；可变升级速度在所有“＋”翻牌完成后暂停选择，并高亮第 3 步。

## 官方进阶模块

房主在创建房间或大厅中分别勾选「天气与路况」「车库：普通升级」「车库：高级升级」，全部默认关闭。开始后设置锁定，已有比赛继续使用原设置。选牌和比赛状态均写入房间 JSON，刷新或服务重启可恢复。

- **天气与路况**：从 6 种天气中随机选择一整场天气，按官方牌面调整初始压力、引擎与热量分布；12 枚路况（6 种各 2 枚）随机、不放回地分配到各弯道。无路段图标的令牌只影响对应弯道；路段效果覆盖该弯道线后至下一弯道线前，可跨起终点。“天气”路段才应用天气的路段效果。免费加速、尾流和冷却按执行时的位置判断，禁止冷却覆盖所有冷却来源。
- **车库**：每种升级各两张，普通编号 1–17、高级编号 18–48。每轮市场为玩家数 +3 张，三轮依次后→前、前→后、后→前选牌，剩余牌不返回本场选牌堆。每人选出的 3 张升级替换起始 0、5、热量升级，再洗入初始牌库。
- **牌面效果**：支持固定/可变速度、逐个“＋”翻牌、冷却、减压、尾流奖励、必付热量、必弃牌库、个人限速、回收弃牌、追加出牌、每次翻牌加速和保留到抽牌堆顶。所有“＋”在可变速度选择前结算。反应效果顺序由车手选择；必付效果完成后才能进入尾流与弯道检查。热量不足的升级可弃掉并按官方方法翻出随机基础牌替换。
- **查看效果**：改装卡直接标注触发步骤、是否必须执行以及牌的去向。市场、手牌、回合事件和「赛车改装」中的「效果说明」可查看每张卡的完整规则和例子，不会触发选牌或出牌。比赛页面默认展开自己的三张升级，可展开其他玩家的改装；升级是加入牌组的卡牌，需实际打出才生效，额外热量牌需冷却到引擎区。
- **天气路段图示**：赛道用蓝色斜纹和「天气路段」标签标出放有天气路况标记的路段，底纹覆盖格数直接使用结算引擎的路段判定，包含跨起终点的路段。没有天气标记时明确显示本场无天气路段；天气卡的开局调整仍照常应用。
- **其他路段图示**：尾流额外 +1 使用紫色斜纹，免费加速使用橙色点纹，并在起始弯道旁显示路段编号和效果文字。底纹范围与天气路段一样使用结算引擎判定，图例只显示本场出现的路段效果。仅限速调整或超速费用的路况只标在弯道处。
- **保留与异步收尾**：反应阶段选择保留，补牌前放回牌顶，多张按点击顺序从顶抽取。选择保存在各车手身上，不受下一位行动影响。

普通转速表 #14 的尾流奖励为 **+2**；高级车身 #19 同时有 **冷却 1、减压 1、必弃牌库 2**。官方牌面用于校正部分社区列表的遗漏。数据与图标参考 [Days of Wonder 进阶规则 v1.1](https://cdn.svc.asmodee.net/production-daysofwonder/uploads/2025/03/9101-HT-RulesAdvanced-EN_compressed.pdf) 和官方授权 BGA 的牌面图，来源记录在 `lib/modules.ts`；界面使用本程序原创卡片排版。

电脑仍使用本程序的策略，并支持车库选牌、可变速度和合法升级结算。测试不把电脑策略等同于官方 Legends 模块。

## 三款扩展盒：单场比赛

Heavy Rain、Tunnel Vision、Rocky Roads 分别有独立开关，启用一盒容量 +1，全部开启最多 9 人。选择某盒的地图时自动启用该盒；发车后锁定设置。它们不依赖天气模块；新增升级需同时开启对应盒与「车库：高级升级」，可跨赛道使用。新增升级编号 49–66，共 18 种、36 张，混入既有三轮车库市场；必须实际打出，效果只持续自己的本回合。

| 扩展盒        | 赛道   | 格数 | 正式圈数 | 引擎热量 / 压力 | 弯线后首格 : 限速                                                 | 减速弯       |
| ------------- | ------ | ---: | -------: | --------------- | ----------------------------------------------------------------- | ------------ |
| Heavy Rain    | 日本   |   60 |        2 | 7 / 3           | 11:4、13:4、19:2、46:5、54:3                                      | 11–13        |
| Heavy Rain    | 墨西哥 |   60 |        3 | 6 / 2           | 15:7、20:7、39:6、45:4、51:2、52:2                                | 15–20、51–52 |
| Tunnel Vision | 西班牙 |  109 |        1 | 6 / 3           | 12:5、16:4、30:4、33:4、45:2、66:5、86:2、93:3、96:4、99:4、104:3 | 30–33、96–99 |
| Tunnel Vision | 荷兰   |   55 |        3 | 6 / 3           | 10:5、14:5、17:3、27:8、35:4                                      | 10–14        |
| Rocky Roads   | 德国   |   62 |        2 | 5 / 3           | 12:5、24:2、25:2、38:6、46:4、53:4                                | 24–25        |
| Rocky Roads   | 南非   |   71 |        2 | 7 / 3           | 12:4、19:3、25:2、35:6、47:5、56:2、63:4                          | —            |

- **积水（日本，蓝色 ≈）**：第 1 步开始时停在积水车位，降挡额外付 1 热量；降一挡付 1，降两挡付 2，升挡与留挡不加费。两条车道格号 6–11、39–45、50–55。
- **隧道（西班牙，深色 ▥）**：停在隧道时，禁止手牌进弃牌堆，包括第 5 步减压和第 8 步弃速度牌。手牌热量冷却到引擎、超级冷却、弃牌库和第 9 步弃已打出的牌照常。两条车道格号 17–24、38–42、46–49、62–71、80–88。
- **碎石（南非，棕色点纹）**：仅标出的物理车位生效，另一车道可能没有碎石。第 9 步弃已打出的牌后、补牌前，若停在碎石且引擎还有热量，付 1 热量；引擎为空则忽略。图示和规则使用同一组 `terrain` 数据，跨圈按同一车位判断。
- **减速弯（蓝色路肩）**：两条弯线分别检查同一限速。天气与路况只抽一个共用标记；弯道限速和超速费用作用于两条线。路段效果只从出口线后开始，两线之间没有路段效果。
- **超级冷却（进气口，第 5 步，可选）**：从自己的弃牌堆将至多图标数量的热量移回引擎；每个图标本回合一次，可以先付热量/弃牌库再使用。禁止冷却路段也禁止超级冷却。
- **牵引（前翼，第 5 步，可选）**：前进 1 至图标数量格，沿途及落点的两条车道必须全空，落点恰好紧跟另一辆车。多个图标可合用或分别用，各图标一次；不增加速度，可跨最终终点，可在加速前后使用，之后仍可尾流。界面只列出当前位置的合法落点。
- **连续尾流（滑动裙板，第 6 步，可选）**：普通尾流后，每个图标允许再尾流一次；每次在新位置重新检查资格、天气及路况，升级尾流奖励重复适用。可以提前停止，完成后一次性逐弯检查；不增加速度，不可跨最终终点，也不可回到第 5 步。

地图旁说明地形和开局参数，玩法指南与每张卡的「效果说明」注明使用步骤、可选/必付及例子。程序保留用户指定的几何内侧与异步收尾方式；官方传奇车手、赞助卡和锦标赛未纳入此次单场范围。九人仅普通车库时，实体 34 张普通牌不足以每轮都保持人数 +3，最后一轮使用剩余牌，仍能每人选满三张。

规则核对来源：[Heavy Rain 官方规则](https://cdn.svc.asmodee.net/production-daysofwonder/uploads/2025/03/HTEX1-Rules-EN-FC.pdf)、[Tunnel Vision 官方规则](https://cdn.svc.asmodee.net/production-daysofwonder/uploads/2025/02/9103-HTEX2_EN_RULES_20240924_compressed.pdf)、[Rocky Roads 官方规则](https://cdn.svc.asmodee.net/production-daysofwonder/uploads/2026/01/HTEX3_EN_HEAT_Rocky_Road_RULES.pdf)。地图格数、地形车位和卡面编号交叉核对[官方授权 BGA 数据](https://github.com/bga-devs/bga-heat/tree/master/modules/php)；仅转录规则事实，使用独立规则实现和原创界面，不分发其源码或官方美术。

## ParrotVPN 部署

服务器使用 Node.js 24 + SQLite + Docker + Nginx；构建在本机完成，远端只运行约 44 MB 的 standalone 产物，不安装开发依赖。Sites 的默认构建仍使用 Cloudflare Workers / D1。

```sh
# 本机 Node 版（自动创建 data/heat.sqlite，无需手动建表）
npm run build:node
npm run start:node
# 本机已配置 SSH Host ParrotVPN，源码提交后部署
bash scripts/deploy-parrot.sh ParrotVPN
# 验证公网完整比赛
HEAT_TEST_URL=https://52.76.213.199/heat HEAT_TEST_TRACK=italy HEAT_TEST_FORMAL=1 node tests/network.test.mjs
node --test tests/node-store.test.mjs tests/request-id.test.mjs
# 在已启动的 Node 服务上验证全部 8 种模块组合：
HEAT_TEST_URL=http://localhost:3000 node tests/modules-network.mjs
# 全扩展的双客户端正式赛（逐一切换六个新 trackId）：
HEAT_TEST_URL=http://localhost:3000 HEAT_TEST_PACKS=1 HEAT_TEST_MASK=7 HEAT_TEST_FORMAL=1 HEAT_TEST_TRACK=japan node tests/modules-network.mjs
# 真实九客户端入房、权限、席位恢复和容量边界：
HEAT_TEST_URL=http://localhost:3000 node tests/expansions-network.mjs
```

远端源码与构建在 `/srv/heat-online/releases/<Git SHA>`，当前版本链接为 `/srv/heat-online/current`，比赛数据库在 `/srv/heat-online/data/heat.sqlite`。容器 `heat-online` 仅绑定 `127.0.0.1:18766`，通过已有 Nginx 的 HTTPS `/heat/` 路径提供服务，复用公网 IP 证书；HTTP 80 跳转到此入口，保留 ZVal 的 HTTPS 根路径服务和 HTTP ACME 验证路径。容器使用非 root 用户、只读根目录、512 MB 内存上限、日志轮转和 `unless-stopped` 自动重启。

```sh
ssh ParrotVPN 'sudo docker stats --no-stream heat-online'
ssh ParrotVPN 'sudo docker logs --tail 50 heat-online'
ssh ParrotVPN 'sudo docker restart heat-online'
# SQLite 在线一致性备份（首次或每次备份使用不同文件名）
ssh ParrotVPN "sudo docker exec heat-online node --input-type=module -e 'import {DatabaseSync} from \"node:sqlite\"; new DatabaseSync(\"/data/heat.sqlite\").prepare(\"VACUUM INTO ?\").run(\"/data/heat-backup.sqlite\");'"
```

若自行改用 HTTP 公网 IP，浏览器使用 `getRandomValues` 生成请求标识，兼容不提供 `randomUUID` 的非安全上下文。刷新或服务重启后，只要浏览器身份 cookie 仍在且房间未过期，即可恢复座位。首次部署不会复制 Sites 上已有比赛。

## 程序结构

- `lib/tracks.ts`：赛道参数；`lib/track-geometry.ts`：按格数绘制的赛道几何。
- `app/circuit.tsx`：赛道、弯线和赛车的 SVG 渲染。
- `lib/modules.ts`：全部 66 种升级、天气与路况牌面数据；`app/modules-ui.tsx`：开关、车库、天气参考和升级操作。
- `lib/game.ts`：服务器共用的规则引擎、电脑策略与隐私视图。
- `app/api/rooms/route.ts`：房间、身份和操作接口。
- `app/page.tsx`、`app/globals.css`：中文响应式界面和 SVG 赛道。
- `db/schema.ts`、`drizzle/`：Cloudflare D1 房间持久化。
- `tests/`：规则与联网测试。

前端每 1.7 秒查询最新房间状态。每次行动由服务器校验，D1 使用版本号条件更新避免同时写入覆盖；请求标识避免成功行动被重复执行。其他车手的未公开手牌与牌库不发送到客户端。Cookie 身份使用 HttpOnly 与 SameSite=Lax。

行动提交期间暂停常规轮询，界面显示同步状态。并发操作若发生版本冲突，服务器返回当前玩家的最新隐私视图，客户端保留请求标识自动重试，避免额外读取房间的网络往返。选中的弃牌只随自身阶段或手牌变化清空，不受其他车手行动影响。POST 响应的 Server-Timing 记录处理耗时，可与完整请求耗时比较定位延迟。

项目使用 Vinext / React / Cloudflare Workers / D1，通过 Sites 托管。发布配置保存在 `.openai/hosting.json`；源码包不含访问凭据、线上比赛数据或本地数据库。
